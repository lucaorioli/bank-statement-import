Online Bank Statements: Field Mapping

This module lets you choose, for each online bank statement provider, which fields of the statement lines are filled from the raw data of the transactions, and how.

It works with the providers that keep the transaction as JSON in the raw data of the lines (for instance Stripe, PayPal or Ponto), and with any field of the statement lines: the standard ones, the common transaction details of account_statement_import_base or fields added by other modules. The fields that define the transaction and its journal entry (amount, date, journal, currencies…) cannot be mapped.

Configuration

  1. Go to Invoicing > Configuration > Online Bank Statement Providers and open a provider.
  2. In Field Mapping, add a line for each field to fill: the Expression gives the value, the Field where to write it.

An expression is the path of a value of the raw data in braces, for instance {source.billing_details.email}, possibly within some text, for instance Invoice {invoice.number}. Elements of a list are reached by their position: {items.0.name}. Alternatives separated by | are tried in order, until one gives a value: {source.payment_intent} | {source.id}.

The value is converted for the field: dates and datetimes from Unix timestamps or ISO strings, numbers, booleans, and records of many2one fields by name or code (for instance a country from IT). A value that cannot be converted is left out.

When several lines fill the same field, the first one that gives a value is used.

Usage

The mapping is applied to the lines created by each pull.

To apply it again to lines already imported, for instance after changing it, select them in the list of the statement lines and use Actions > Reapply Field Mapping. On reconciled lines, the label and the partner are not changed, because that would rewrite their journal entry.
